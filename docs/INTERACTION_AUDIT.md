# 0.7.1 交互入口排查

日期：2026-11-15。构建与实际通过记录见 [VALIDATION.md](VALIDATION.md)，设计与来源见 [ADR 0011](adr/0011-photo-picker-and-stable-actions.md)。

| 入口 | 已处理的问题 | 实现及验证 |
|---|---|---|
| 导入作品 / 位图 | 图片使用文档界面、取消和遗留选择器状态不明确 | Photo Picker / 旧相册 ACTION_PICK；请求独立编号；取消、空结果、异常反馈；重复打开/返回及相册流程 |
| SVG / G-code / JSON | 启动失败或旧回调影响后续选择 | 保留文档接口和内容白名单，启动失败复位请求；旧编号结果丢弃 |
| 格式、算法、串口、控制线选项 | 排版重建按钮，触摸可能落在即将移除的对象 | 预建稳定按钮，只更新可见范围；页面版本阻止失效回调 |
| 开始 / 继续 / 取消及其他异步按钮 | 定时刷新覆盖禁用状态；结束后直接启用不符合实际状态 | 统一忙碌集合；刷新遵守忙碌状态，完成后按任务/设备条件恢复；确认返回及暂停继续流程 |
| 生成任务 | 通用点击锁与取消生成共用按钮存在冲突 | 该按钮允许再次点击取消，转换本身保持单个任务；原有取消与修订检查继续验证 |
| 任务库项 / 启动恢复 | 异步读取旧任务后覆盖新操作、关闭新菜单 | 数据结果检查读取版本与参数修订，导航同样检查读取版本 |
| 导出任务 / 导出日志 | 返回系统页面时取到变化后的选择，取消/成功缺乏明确反馈 | 点击时固定任务/日志并缓存，跨页面恢复独立编号；完成、取消与失败均清理状态并反馈 |
| 体验完整演示 | 固定等待 450 ms 后直接就绪，繁忙时配置未完成 | 等待现有协议判定的 CanArm 状态；配置 ACK 和后续新 Idle 回归 |
| 面板返回 / 底部导航 / 回前台 | 遗留覆盖层、旧布局回调和动画状态影响后续页面 | 关闭时无条件移除触摸覆盖层，失效页面版本；恢复前台复位动画并维持单个刷新循环 |
| USB 授权与硬件操作 | 检查等待、异常及未连接反馈 | 沿用有界 60 秒 USB 授权等待和统一异常提示；硬件操作仍由 DeviceSession 校验状态与协议 |

本轮不增加运行时依赖，复用 Android Intent、Photo Picker、ContentResolver、原生 Views、Task 与现有校验/设备会话。

模拟器测试使用公共图片和固定夹具，真实系统相册接口负责选图；返回后由现有 Skia 校验真实内容。厂商 ROM 相册和实体 USB 测试独立记录。
